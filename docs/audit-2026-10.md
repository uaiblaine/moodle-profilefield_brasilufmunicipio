# Audit and fleet standardisation, October 2026

Full audit of the plugin as imported from upstream (`origin/main` at `dc0d9b7`, release 17): the Moodle skills
(security, privacy, capabilities, web services, plugin development, strings, upgrade, AMD, accessibility), a comment
audit of every file, and an independent adversarial read of the result. Each finding below was fixed unless its
verdict says otherwise; the tests that hold the fixes are named in `mutations/gates.conf`.

## Defects

| # | Finding | Verdict |
|---|---|---|
| 1 | A UF without a municipality ran `WHERE ibgeid = ''` on an integer column: `dml_read_exception` on PostgreSQL, from the profile page, sign-up and `enrol_apply`. A code of 19+ digits failed the same way. | Fixed: `api::is_ibgeid()` (1 to 10 digits) guards every lookup. |
| 2 | With both selects empty the hidden element's `1` was stored, so a required field counted as filled. | Fixed: `''` is stored, and `is_empty()` reads old `1` rows as empty. |
| 3 | A CSV upload or a user web service had its value ignored (the selects are not in their data); the upload form draws the selects too, so the request alone cannot tell the paths apart. | Fixed: the path is decided from the value; external values go through `convert_external_data()` (`UF / name` or the JSON); `tool_uploaduser` reports an unusable value, the web services get an exception. |
| 4 | A locked field could be changed by posting the selects: core freezes only the hidden element. | Fixed: preprocess keeps the stored value, and the selects are frozen. |
| 5 | An IBGE error or empty answer deleted the UF's municipalities until the next monthly run; no timeout, no status check. | Fixed: a UF keeps its rows unless the answer is HTTP 200 with a well-formed list; the tasks fail so they are retried; 30 s timeout. |
| 6 | 27 requests to IBGE ran inside an upgrade step; a fresh install had an empty list until day 2 of the next month. | Fixed: `db/install.php` and the upgrade step queue an adhoc task. |
| 7 | Overlapping refreshes (adhoc + scheduled) could store a UF's list twice; `get_record()` then emitted a debugging error on save. | Fixed: refreshes hold a core lock; the lookup tolerates an existing duplicate. |
| 8 | No privacy provider, although every value lives in `user_info_data`. | Fixed: full provider mirroring core's `profilefield_text`, with `component_is_compliant()` asserted. |
| 9 | `display_data()` printed the stored UF and name unescaped (report builder and the profile print it as HTML). | Fixed: escaped, and a UF outside the 27 is not shown. |
| 10 | A field saved with no UF selected stored `''` in `param1`, which offered one blank UF instead of all of them. | Fixed. |
| 11 | JS: the change listener passed the Event as the municipality to select; comparisons with the string `'undefined'`; no empty option (the client required rule meant nothing); `innerHTML`; no failure handling; a stale answer could fill the select. | Fixed: ES module rewrite. |
| 12 | A required field was checked only in the browser. | Partly fixed: the UF is checked on the server too. The municipality cannot be: `enrol_apply` validates through a web service form whose request does not carry it. |
| 13 | The web service returned municipalities in no particular order. | Fixed: sorted by name. |
| 14 | Upgrade step 2022030304 was guarded by `< 2022030301`, and re-encoding a non-JSON value stored the string `null`. | Fixed. |
| 15 | `$plugin->requires` said "Moodle 5.0" but named 4.2; no `$plugin->supported`. | Fixed: requires 4.5, supports 4.5 to 5.3. |

## Standards

GPL headers and docblocks on every file; phpcs and phpdoc at zero warnings; `lang/pt_br` in lockstep (export-ignored);
the three hardcoded UF lists merged into `api::get_ufs()`; the unused `availableufs_desc` became a help string; README,
CHANGELOG, `LICENSE` + `COPYING.txt`, `.gitattributes`, CI workflow (4.5, 5.1, 5.2, 5.3), the readiness test, data
generators and a Behat scenario of the real user flow. Daniel Neis Araujo's copyright stays on his files.

## Comment audit

Every comment of the imported code was rewritten or removed: three file docblocks described another plugin ("Static
Text profile field", "Text profile field definition", "Handle opening a dialogue to configure condition data"), the web
service's said it "finds users with the identity matching the given uf", and the upgrade file carried the XMLDB
editor's boilerplate. New comments state only what the code does not.

## Left for the owner

- Rows stored as `1` by earlier versions now count as empty: a user holding one in a **required** field is asked to fill
  it in at the next login.
- Sites on Moodle 4.2 to 4.4 can no longer install this version.
- `.gitlab-ci.yml` (upstream's GitLab SAST) is kept but export-ignored.
